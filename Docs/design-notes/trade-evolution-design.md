통신교환 진화(스라크→핫삼, 고우스트→팬텀 등) 전달 방식 설계(6/22). 진화 3분할([[project_meeting_0617]]) 중 세 번째 루트. 진화의 돌([[project_evolution_stone_design]])과 달리 **취소 불가·즉시 진화**.

## 확정: 모델 (A) 1마리 핸드오버 → 그 1마리만 진화 → A 벤치 직행
(B) "교환 트리거→상점에 진화체 교체"는 기각. 이유: 상점=리롤로 사라짐+골드 의미 충돌(진화의 돌 때 걷어낸 문제 재발), 진화체는 풀 밖이라 상점 주입이 해킹성.
- 전달 위치 = **상점 아님, 벤치 직행**. 구매 경로(`HasBenchSpace`+`TryPlaceInBench`) 재사용, 골드 0, 취소 불가.
- 권위: 동기화 설계([[project_sync_design]]) "각자 보드 각자 권위" → 전송은 **베이스 종+통신진화 플래그만** 넘기고 **A 클라가 자기 권위로 진화체 인스턴스화**. TradeEvolutionData 조회도 A쪽.
- 벤치 꽉 차면 전송 거부(B에게 피드백). NetworkManager에 전송 트랜잭션 신규 필요(현재 보드 미러 스냅샷만 있음, transfer 미구현).

## obtainBy 매핑 (이미 만든 shopBuyable 파이프라인 재사용)
- 베이스(스라크/고우스트) → `obtainBy=shop`(또는 빈값), 풀에 있음 = 통신진화 재료
- 진화체(핫삼/팬텀) → `obtainBy=trade`, 풀 제외, 통신교환으로만 획득

## 데이터 정정 필요
`TradeEvolutionData.cs` 주석 "양쪽 필드+대기석 동일 포켓몬 모두 진화체로 변환"은 모델 (B) 광역변환이라 (A)와 충돌 → **"전송된 그 1마리만 진화"로 수정** 필요(아직 안 함).

## ⚠️ 미확정 — 재미/비용 설계 (★6/23 회의 안건: 풀 모델 확정하기로)
질문: 높은 성급 통신진화가 필요하면 B가 자기 골드로 2성 스라크(=3마리) 맞춰 헌납 → 한쪽 호구 느낌, 재미있나?
- 비용 재프레이밍: 2성 핫삼=2성 스라크=3카피, **일반 2성과 동일**. 추가비용은 트레이드 행위+조율뿐(별값 자체는 정상).
- **내 추천(미확정): 각자 풀 + "양쪽 카피 합체"** — A 스라크1 + B 스라크2를 트레이드 시 합쳐 2성 핫삼. 한쪽 희생 아닌 "둘이 같이 만드는 협동 이벤트". 실제 통신교환 감성과도 일치.
- 재미 조건: 통신진화체는 페이오프/키 시너지 유닛이어야, 그리고 유일경로 아닌 선택지여야(자발적 마찰).
- **정할 것: ①풀 공유 vs 각자 ②트레이드=1마리전송 vs 양쪽카피합체.** 대안: 일단 1마리전송 단순구현 후 밸런스 차후.
