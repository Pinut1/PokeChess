## 🎯 1순위: 임포터 / 데이터 시트 우선 (2:4 구조 레버리지)

> **원칙:** 개발 2명은 *콘텐츠*가 아니라 *시스템 + 임포터*만 만든다. 포켓몬·시너지·스테이지를 손으로 박지 말고,
> 기획·아트 4명이 **데이터 시트로 자급(self-serve)** 하게 만든다. 콘텐츠는 싸고(4명), 시스템은 비싸다(2명).
> 개발이 "이번에 지원하는 효과/필드 범위" 명세를 먼저 주고, 기획은 그 안에서 시트를 채운다(게이트).

**개발이 먼저 시스템화할 것 (이게 풀리면 4명이 바로 일 시작):**
- [ ] `PokemonData` 시트 컬럼 확정 + `PokeChessImporter` 확장 — 마나/스킬/role/시너지 필드까지 임포트
- [ ] **시너지 효과 제네릭화** — `SynergyData`에 구조화된 효과 타입(스탯버프 / 보호막 / 추가데미지 등 3~4종) 필드 + 임포터 → 기획이 12시너지를 데이터로 조립
- [ ] **Stage Table / Trainer Entry 임포터** (Wild/Trainer/Boss) → 기획이 5~7라운드 적 구성 채움
- [ ] `Reward Table` 임포터 → 라운드 보상 데이터화
- [ ] Item/Augment 시트 **스키마만 미리 확정** (시스템 구현은 후순위라도 기획이 채워둘 수 있게)

**그 다음 콘텐츠는 비개발 인력이 채움:**
- 기획: 위 시트 채우기(포켓몬 8~12종, 시너지 3~4개부터, 스테이지 5~7) / 밸런싱
- 아트: 캡슐·큐브 → 실제 모델/카드 일러스트 최소분 교체

- [ ] 통신기 UI 트리거 (UI 파트와 연동) — ⚠️ **모델 확정 전까지 홀드** (아래 🔺 해결 후 착수)

> 🔺 **통신교환 재설계 필요 (7/22 확인 — 설계 뒤집힘, 미해결)**
>
> **현재 코드**: 모델A. 내 벤치 유닛 1마리를 파트너에게 전송 → 받는 쪽 벤치에 (매핑 시)진화체 1마리 생성, 보낸 쪽에서 제거. 상점·필드·대기석은 **미영향**. (`NetworkManager.SendTradeUnit`/`RPC_TradeReceive`)
>
> **최종 확정 방향(영욱, 7/22 + Pokemon DB 가이드 TradeEvolution 시트)**: **즉시진화 + 광역변환**. 통신기에 올리는 순간 즉시·비가역 진화(예: 스라크→핫삼)하고, 실행 플레이어의 `affectsField`/`affectsBench`/`affectsShop`=TRUE — 내 필드·대기석의 동일 원본도 진화체로 고정되고, **이후 내 상점에도 원본 대신 진화체(핫삼)만 등장**. `isReversible`=FALSE.
>
> → 이는 6/22에 **기각했던 모델B 계열**이다. 즉 설계가 뒤집혔고 코드는 옛 결정(모델A)에 묶여 있음. 재작업 시:
> - `TradeEvolutionData`에 `affectsField/Bench/Shop`·`isReversible` 필드 추가 + 임포터
> - 상점/공용 풀 처리: 진화 후 그 플레이어 상점에서 원본→진화체 치환. **공용 풀 예약(#42)과 어떻게 상호작용할지 설계 필요** (이미 예약된 원본 슬롯 처리 포함)
> - 필드 진화 시 시너지/역할군 재계산(진화체 데이터 기준) 트리거
>
> **아직 기획 확인 필요(황해인)** — 재작업 전 반드시 선확정:
> - **스탯 배율 3중 불일치**: 메인 기획서 `×1.4` vs DB 가이드 특수진화 `2성 ×2.0/3성 ×3.0` vs 현재 코드 `StarMult(1.8/3.24)×1.5(PLACEHOLDER)`. 어느 게 최종인지
> - ⚠️ **계산식 함정**: DB 가이드대로 "진화체 시트값 = 2성 기준 직접입력"이 최종이면, 현재 `data.hp × StarMultiplier × 1.5` 는 **2중 적용(스탯 뻥튀기) 버그**가 됨 → 계산식 구조 자체를 다시 잡아야 함
> - **발동 조건**: 통신진화가 2성 이상인지, 정확히 2성만인지 (현재 코드는 성급 제한 없음)
> - **파트너 관여 여부**: "통신"이라 파트너와의 교환이 트리거인지, 아니면 진화의 돌처럼 셀프 트리거인지 (모델A는 핸드오버였음)
