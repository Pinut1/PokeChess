## 🎯 1순위: 임포터 / 데이터 시트 우선 (2:4 구조 레버리지)

> **원칙:** 개발 2명은 *콘텐츠*가 아니라 *시스템 + 임포터*만 만든다. 포켓몬·시너지·스테이지를 손으로 박지 말고,
> 기획·아트 4명이 **데이터 시트로 자급(self-serve)** 하게 만든다. 콘텐츠는 싸고(4명), 시스템은 비싸다(2명).
> 개발이 "이번에 지원하는 효과/필드 범위" 명세를 먼저 주고, 기획은 그 안에서 시트를 채운다(게이트).

**개발이 먼저 시스템화할 것 (이게 풀리면 4명이 바로 일 시작):**
- [ ] `PokemonData` 시트 컬럼 확정 + `PokeChessImporter` 확장 — 마나/스킬/role/시너지 필드까지 임포트
- [ ] **시너지 효과 제네릭화** — `SynergyData`에 구조화된 효과 타입(스탯버프 / 보호막 / 추가데미지 등 3~4종) 필드 + 임포터 → 기획이 12시너지를 데이터로 조립
- [ ] **Stage Table / Trainer Entry 임포터** (Wild/Trainer/Boss) → 기획이 5~7라운드 적 구성 채움
- [ ] `Reward Table` 임포터 → 라운드 보상 데이터화
- [ ] Item/Augment 시트 **스키마만 미리 확정** (시스템 구현은 후순위라도 기획이 채워둘 수 있게)

**그 다음 콘텐츠는 비개발 인력이 채움:**
- 기획: 위 시트 채우기(포켓몬 8~12종, 시너지 3~4개부터, 스테이지 5~7) / 밸런싱
- 아트: 캡슐·큐브 → 실제 모델/카드 일러스트 최소분 교체

> 🔺 **통신교환 재설계 — 기획 확정 + 구현 동결 (7/22)**
>
> **확정 방향(황해인 확정 7/22)**: **즉시진화 + 수신자 광역변환**. 통신기에 유닛을 올리면 파트너에게 **실시간 단방향 전송**(상호 교환 불필요), 받은 플레이어에게 그 원본 종이 **즉시·비가역 진화체로**, 그리고 **수신자의 필드·대기석·현재 상점(잠긴 슬롯 포함)·이후 상점**까지 광역 즉시변환. 매치 내내 영구 + 재접속 복구. 발동 성급 제한 없음(성급 유지 종 교체). 경제(구매가·판매환급·공용풀 반환)는 **원본 기준**. 장착물 승계.
>
> **구현 상태(7/22 작업본)**: 스키마/임포터, 유닛 영구 종교체·비주얼, 보드·벤치 일괄변환, 상점 override/원본풀 분리, 네트워크 수신 발동, Player CustomProperties 저장·재접속 복구까지 구현. 현재 워크트리에 미커밋 상태이며 Unity 컴파일 0에러, 7개 매핑 Import, 보드·벤치·상점 에디터 진단을 통과했다.
> - **잔여**: 정상 연결 기준 Photon 2클라이언트 행복경로 회귀 테스트만 수행. 통신기 정식 UI는 담당 작업 완료 후 연결한다.
> - **의도적 스코프 제한**: ACK 직전 연결 단절이나 RPC 중복을 위한 트랜잭션 ID·재전송 원장·exactly-once 처리는 포트폴리오 범위에서 제외한다. 위험은 인지하되 정상 플레이 완성도와 QA에 공수를 우선한다.
> - 구현 핵심: 공용 풀/가격/반환은 원본 ID, UI·생성은 진화체 데이터, 활성 원본 목록은 `TradeEvos` Player CustomProperties로 보존한다.
>
> **아직 열린 것 2가지 (병합 전 확인):**
> - **스탯 기준(투자문서 8번)**: 진화체 시트 스탯이 1성 원본기준인지 2성 완성값인지 미확정. 현재 식 `시트스탯 × 성급배율 × 1.5`는 **1성 기준 가정**. 2성 기준이면 성급배율 이중적용(~2.7배) → 계산식 수정 필요. `×1.5`(`SPECIAL_EVOLUTION_MULTIPLIER`) 자체는 설계 의도(강화)라 유지.
> - **매핑 삭제 검증**: CODEX가 trade_evolution 매핑 9→7로 줄임(Abra→Kadabra·Geodude→Graveler를 "잘못 추가된 중간진화 행"이라며 삭제, Slowking→Wobbuffet 정정). 규칙 확정과 별개인 **데이터 결정**이라 황해인 최종 확인 권장.
