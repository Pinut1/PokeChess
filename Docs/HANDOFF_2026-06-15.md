# 작업 핸드오프 — 2026-06-15 (오전)

## 개요
샵→벤치→보드 드래그앤드롭 루프, 합성(일반진화), 판매, 플레이어 체력/패배/게임오버까지 구현.
라운드 루프에 승패의 의미(판돈)가 생겨 "시작과 끝이 있는 게임"의 골격이 완성됨.

## 한 일

### 1. 시너지 전투 버프 — 시도 후 보류
구조(effectType/effectValue + ApplySynergyBuffs)까지 만들었다가, 시너지 밸런스가 디자인상 미확정이라
가짜 수치 베이킹을 막기 위해 코드·JSON 전부 원복. 플랜만 보존(`PLAN_2026-06-15_synergy-battle-buffs.md`).
→ 디자인 확정되면 그 문서대로 재구현.

### 2. 샵 → 벤치 → 보드 드래그앤드롭 루프 + 합성 ✅
- `ShopManager`(스텁→구현): 골드 경제, 롤/구매/리롤, 라운드 수입
- `UnitFactory`: PokemonData → PokemonUnit 생성 단일 창구
- `BenchTile` + `BoardManager.GenerateBench`: 벤치 슬롯 시각화 + 드롭(스왑 포함)
- `BoardView`: 배치/벤치/판매 이벤트 → 유닛 위치 재배치(논리/뷰 분리)
- `UnitDragController`: 마우스/터치 드래그앤드롭
- 합성(GDD 4.2 일반진화): `BoardManager.CheckEvolution` — 같은 종 3개 → 별업, 연쇄(★→★★→★★★)
- `ShopDebugTest`: 드래그 없이도 구매/리롤/합성 테스트

### 3. Input System 대응 ✅
레거시 `Input` → 새 Input System → 임베드 InputAction → 바인딩 `<Pointer>`.
결과: 에디터(마우스)·안드로이드(터치)가 코드 수정 없이 동일 동작.

### 4. 판매(Sell) ✅
- `BoardManager.SellUnit`: 제거 + `OnUnitSold` 발행(처음으로 실제 발행)
- `ShopManager.SellValue`: cost × (1성1/2성3/3성9) 전액 환급
- `SellZone`(드래그 판매) + ShopDebugTest 판매 버튼

### 5. 플레이어 체력 · 패배 · 게임오버 ✅
- `PlayerHealthManager`: 패배 시 체력 -10, 0이면 `SessionEnded → GamePhase.GameOver`(기존 경로 재사용)
- `GameEvents.OnHealthChanged` 추가, `GameManager.PlayerHealth` 등록
- 순서 가드: RoundPhaseManager가 GameOver를 Result로 덮어쓰지 않게(`if(CurrentPhase==GameOver) return`)
