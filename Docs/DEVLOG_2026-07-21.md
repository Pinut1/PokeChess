## 1. 임포터 데이터 검증 (PR #51)

`stage_data` ↔ `trainer_entry_data` join에서 관계형 키 문제가 조용히 넘어가고 있었다.

### 문제

- 중복 `trainerId`가 있으면 **마지막 값으로 조용히 덮어썼다** (`map[id] = trainer`)
- 누락 `trainerId`는 스테이지마다 경고를 뱉어 콘솔이 도배됐다
- 엔트리는 있는데 `enemies`가 비어 있는 경우는 **아무 경고도 없었다**

### 수정

중복은 에러로 보고하고 첫 엔트리를 유지, 누락은 참조 스테이지별로 집계해 1회 출력, 빈 `enemies`는 누락과 분리해 별도 경고. 어떤 스테이지도 참조하지 않는 고아 `trainerId`도 보고한다.

### Import 중단 도입

조사 중 더 큰 문제를 발견했다. **stage_data의 인라인 `enemies`가 전 스테이지 0마리**라 "전환기 폴백" 경로가 이미 껍데기였다. 즉 `trainerId` 오타 하나면 폴백이 구제해주는 게 아니라 **적 0마리 스테이지가 조용히 저장**된다.

중단 조건:

| 조건 | 처리 |
|---|---|
| `trainerId`는 있는데 엔트리 없음 | 중단 |
| 중복 `trainerId` (어느 쪽이 맞는지 모호) | 중단 |
| 결과적으로 적 0마리인 스테이지 | 중단 |
| 미참조 `trainerId` | 경고 |

"적 0마리 = 항상 결함"의 근거는 `StageType` 4종(`WildCommon`/`WildRare`/`GymBattle`/`ChampionBattle`)이 **전부 전투**라는 것이다. 비전투 스테이지 타입이 추가되면 이 전제를 재검토해야 한다.

진단을 에셋 쓰기 **전**으로 옮겨, 중단 시 `StageDatabase.asset`을 아예 건드리지 않게 했다. 기존에는 저장 후 로그 순서라 깨진 데이터가 이미 기록된 뒤에 에러가 떴다.

### 검증

`GYM_R3`에 오타를 주입해 실제로 중단되는지 확인했다.

```
⚠ trainer_entry_data에 trainerId 'GYM_R3_TYPO' 없음 — 참조 스테이지: 1-3
✖ 적이 한 마리도 배치되지 않은 스테이지 1개: 1-3
⚠ 어떤 스테이지에서도 참조하지 않는 trainerId 1개: GYM_R3
✖ 스테이지 Import 중단 — StageDatabase.asset은 변경되지 않았습니다.
```

오타 하나가 **양쪽에서** 잡힌다 — 새 ID는 "누락"으로, 원래 ID는 "고아"로. 중단 전후 `StageDatabase.asset`의 md5가 동일함을 확인한 뒤 데이터를 원복했다.

## 2. 테스트 seam 확보 — 이 프로젝트 첫 EditMode 테스트

### 막힌 지점

`PokeChessImporter`에 테스트를 붙이려 했으나 불가능했다. **asmdef 기반 테스트 어셈블리는 predefined assembly(`Assembly-CSharp-Editor`)를 참조할 수 없다**(Unity 제약). 기존 `SceneStabilityTests`가 도는 건 UnityEditor API만 쓰고 프로젝트 코드를 안 건드리기 때문이었다.

### 우회

진단 로직만 **의존성 없는 순수 클래스**(`TrainerEntryDiagnostics`)로 분리해 전용 asmdef `PokeChess.Editor.Diagnostics`에 배치했다. `autoReferenced: true`라 `Assembly-CSharp-Editor`가 자동 참조하고, 테스트 asmdef도 참조할 수 있다.

결과: 임포터 테스트 **0개 → 16개**. 중복/누락/빈 enemies/미참조/대소문자/레거시/클린 케이스 + 중단 판정 5종 + 불변식 1종.

### 정공법은 보류

전체를 이렇게 하려면 `Scripts/`에 런타임 asmdef, `Scripts/Editor/`에 에디터 asmdef를 만들어 predefined assembly에서 탈출해야 한다. `_Project/Scripts` 밖의 `.cs`는 서드파티 데모뿐이라 충돌 위험은 낮다.

다만 **지금은 `Assembly-CSharp`가 Photon을 자동 참조하지만, 자체 asmdef로 옮기면 `PhotonUnityNetworking`·`PhotonRealtime` 등을 전부 명시적으로 참조 추가해야 한다.** 첫 시도에 컴파일 에러가 대량 발생하므로 수료 직전에 착수하면 빌드가 깨진 채 인수인계될 위험이 있다. 근거와 함께 `CLAUDE.md` 기술 부채 🔺에 남기고 보류했다.

## 4. 밸런스 시트 대조 하네스 (PR #53)

밸런스 검산을 엑셀(`PokeChess_Balance_Tool.xlsx` 1v1 시뮬레이터)에서 눈으로 하고 있어, 이를 씬에서 자동 판정하게 만들었다.

### 시트와 코드가 일치함을 먼저 확인

| 시트 값 | 코드 계산 | |
|---|---|---|
| 꼬부기 경감계수 0.77 | `100/(100+30)` = 0.7692 | ✅ |
| 파이리 경감계수 0.69 | `100/(100+45)` = 0.6897 | ✅ |
| 꼬부기 평타 DPS 9.6 | `25 × 0.5 × 0.7692` = 9.615 | ✅ |
| 꼬부기 TTK 67.6초 | `650 / 9.615` = 67.6 | ✅ |

꼬부기 TTK가 소수점까지 맞는 게 의미 있다. 꼬부기는 스킬이 `SHIELD`(딜 0)라 평타만 쓰므로, 시트와 코드가 *같은 계산*을 한다는 교차 검증이 된다.

### 설계

공식을 하네스에 **복사하지 않고** `BattleManager.Mitigation`을 직접 호출한다. 복사해두면 코드가 시트와 어긋나도 하네스는 계속 PASS를 내서 검증 의미가 사라진다. 이를 위해 `Mitigation`/`CritFactor`를 `public`으로, `Units` 접근자를 추가했다(읽기 전용, 동작 변경 없음).

씬에는 **일부러 붙이지 않았다.** 다른 디버그 하네스는 `GameSceneTest`의 `GameManager`에 붙어 있지만, 씬 파일은 머지 충돌 시 복구가 어려워 공유 씬 변경을 피했다. 쓸 때 직접 Add하고 저장 없이 제거하는 절차를 `HANDOFF`에 기재했다.

### 리뷰로 좁힌 범위

codex 지적 2건을 반영하며 **문서가 주장하던 검증 범위가 실제보다 넓었음**을 인정하고 좁혔다.

- 밸런스 시트 원본을 직접 확인한 결과 1v1·Data·상수 탭 **어디에도 크리 항목이 없다.** 검증할 기대값 자체가 없으므로 없는 근거로 검증을 만들지 않고 `CritFactor`는 표시만 하도록 문서를 정정했다
- 평타 DPS는 하네스가 `ATK × AS × Mitigation`으로 자체 계산한다. 시트의 DPS 모델을 재현한 것이지 전투 경로를 태운 값이 아니다 — 실제 전투는 `효과(OnDealDamage) → CritFactor → Mitigation` 순서라 효과와 크리가 빠져 있다. 이 단서를 상단 주석·계산부·화면 각주 세 곳에 남겼다

배경 `GUI.Box`가 고정 320px인데 내용이 최대 506px까지 나가 삐져나오는 문제도 함께 고쳤다(동적 계산). 측정과 그리기가 어긋나면 무의미하므로 줄 수 계산을 Draw 쪽과 동일한 분기로 구현했다.

## 오늘의 교훈 — Unity MCP가 다른 프로젝트를 보고 있었다

작업 중반에 큰 헛발질이 있었다. 오르카 워크스페이스(git worktree)에서 파일을 고치는 동안, **Unity는 본체 체크아웃(`Documents/Claude/Projects/PokeChess`)을 열고 있었다.** `validate_script`가 그쪽의 옛날 파일을 검사해 0 에러를 냈고, 그걸 "컴파일 통과"로 보고했다.

알아챈 계기는 **새로 만든 파일에 `.meta`가 생기지 않은 것**이었다. Unity가 그 폴더를 보고 있었다면 반드시 생겼어야 했다.

교훈:

- **Unity 쪽 검증을 신뢰하기 전에 `mcpforunity://project/info`의 `projectRoot`가 내 작업 경로와 같은지 확인할 것**
- 보조 신호: 작업 디렉터리에 `Library/`가 없으면 Unity가 연 적 없는 폴더다. 파일을 만들었는데 `.meta`가 안 생기면 Unity가 안 보고 있는 것이다
- 이 프로젝트는 오르카 worktree에서 작업하지 않는다. worktree엔 `Library/`가 없어 Unity로 열면 전체 재임포트가 필요하고, 그러지 않으면 Unity 검증이 전부 무의미해진다
