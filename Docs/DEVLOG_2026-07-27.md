## 1. PR #56 충돌 해결 및 병합

### 상황

PR #56(`art: 유닛 모델/VFX 통일화 및 유닛 상점 UI 실장`)이 `mergeable: CONFLICTING` 상태로 막혀 있었다. 리뷰 0건, 리뷰어 미지정.

충돌은 **`Assets/Scenes/GameSceneTest.unity` 단 하나**였고, 나머지 13개 파일은 자동 병합됐다.

| 브랜치 | 이 파일 변경량 | 내용 |
|---|---|---|
| `master` | +15줄 (커밋 1개) | `StartingUnitGranter` — 게임 시작 시 1코스트 기물 1마리 지급 |
| `haein_asset` | +6243/−518 (커밋 8개) | 유닛 모델/VFX 통일화, 상점 UI 카드 배치 |

### 해결

양쪽 다 살리는 방향으로 수동 해결했다. master의 변경이 작아서(15줄) 그쪽을 haein_asset 결과물 위에 다시 얹는 형태.

충돌 마커는 3곳이었는데, Unity YAML 특성상 **컴포넌트 블록 경계가 어긋나 있었다** — `--- !u!114 &1620688241`(CoinPanel Image)과 `--- !u!114 &1558058679`(StartingUnitGranter)가 같은 `MonoBehaviour:` 헤더를 공유하도록 잘려 있어서, 단순히 한쪽을 고르면 다른 쪽 컴포넌트가 깨진다.

처리 방식:

1. 1번 마커 — HEAD(art) 쪽 `CoinPanel` GameObject/RectTransform 유지
2. 2번 마커 — `&1620688241` 헤더 유지, master의 `&1558058679` 헤더는 제거
3. 3번 마커 — `StartingUnitGranter` 컴포넌트를 **독립 블록으로 재구성**해 뒤에 추가 (`m_GameObject: 1558058640` = GameManager, `_grantCost: 1`, `_grantCount: 1`)

검증: 충돌 마커 0건 + `--- !u!` 블록 292개 + **중복 fileID 0건**(중복이 있으면 Unity가 씬을 못 연다). 이후 해인이 에디터에서 정상 동작 확인.

### 신규 파일

- `Assets/_Project/Scripts/UI/ItemCardUI.cs` — `IShopCardView<ScriptableObject>` 구현. 슬롯 데이터가 `ItemData`/`EvolutionStoneData` 두 타입이라 `Bind`에서 분기(`ShopManager.GetItemShopName`과 같은 패턴)

리롤 버튼은 **`IShopCardView`에 넣지 않았다.** 넣으면 유닛 카드(`ShopCardUI`)까지 없는 기능을 구현해야 해서, `ItemCardUI` 전용 이벤트(`RerollClicked`)로 뒀다. 베이스 클래스도 손대지 않고 `ItemShopBarUI`에서 `Awake`/`OnEnable`만 오버라이드해 배선한다.

### 리롤 모델 변경 (기획디렉터 확정)

**변경 전** — 공용 자원 방식. `RewardKind.ItemShopReroll`로 라운드당 2개 지급, `RerollItemShop()`이 4칸 전체를 굴림. 근거는 `포켓체스_밸런스_기획서.md §7.3 (황해인, v1.0)`.

**변경 후** — 카드별 방식. 각 카드에 붙은 버튼이 **그 슬롯 1칸만** 굴린다. 슬롯당 라운드 1회, 비용 없음, 미사용분 누적 없음.

밸런스 영향: 공용 2회 → 카드별 최대 4회(4장 × 1회)로 더 후해졌다.

| 파일 | 변경 |
|---|---|
| `ShopManager.cs` | `RerollItemSlot(int)`, `CanRerollItemSlot(int)`, `_itemSlotRerollUsed[]` 추가. `RollItemShop()`에서 매 라운드 전부 `false` 리셋 |

### 데이터는 건드리지 않았다

기획디렉터 판단으로 **"데이터 삭제 없이 호출만 끊는"** 방식을 택했다. 다음은 전부 무변경:

- `reward_data.json` — `itemShopReroll: 2` 행 5개 그대로 (읽히지만 `RewardManager`가 무시)
- `RewardKind` enum — `ItemShopReroll` 멤버 유지
- `PokeChessImporter.ParseRewardKind` — `"itemShopReroll"` 매핑 유지
- 구글 시트 / `RewardDatabase.asset` — 재임포트 불필요

이유는 §5에 정리했다.

### 프리팹 배선 상태

`ItemCardContanier_pf`는 **8개 필드 전부 연결 완료**(해인이 직접 배선). `_soldOverlay`는 `Buy_CardFrame_pf` 중첩 인스턴스.

씬에 `ShopCardRow_Item`을 만들고 `ItemShopBarUI` + 카드 4장 배치까지 완료했다.

배선 중 한 번 어긋났던 지점을 기록해둔다. 처음엔 `_cards` 4칸이 전부 아래 형태였다.

```yaml
- {fileID: 4164926895896207906, guid: d2bb4403…, type: 3}   # 4개 모두 동일
```

`guid` + `type: 3`은 **프로젝트 창의 프리팹 에셋 자체**를 가리킨다. 프로젝트 창에서 프리팹을 배열로 직접 드래그하면 이렇게 되고, 씬 인스턴스가 0개라 카드가 렌더링되지 않는다. 4칸이 같은 객체를 가리켜 슬롯 구분도 안 된다.

`ShopCardRow_Item` 하위에 프리팹을 자식 4개로 배치한 뒤 하이어라키의 그 오브젝트를 `Cards`에 드래그해 해결했다. 최종 상태:

| 검증 항목 | 결과 |
|---|---|
| 씬 내 `ItemCardContanier_pf` 인스턴스 | 4개 |
| `_cards` 참조 형태 | `{fileID: N}` (guid 없음 = 씬 인스턴스) |
| 4개 항목 중복 | 없음 |
| 각 항목이 `ItemCardUI`인지 | 4개 모두 |
| 하이어라키 순서 ↔ 배열 인덱스 | 자식[0]→`_cards[0]` … 자식[3]→`_cards[3]` 일치 |

> 씬 배선을 파일로 검증할 때: 씬 인스턴스 참조는 `{fileID: N}`만, 프리팹 에셋 참조는 `guid` + `type: 3`이 붙는다. 이 차이로 오배선을 즉시 구분할 수 있다.

유닛 쪽 `ShopCardRow`가 참고 대상이었다:

- RectTransform `1020 × 150`, Anchor/Pivot `(0.5, 0.5)`
- Horizontal Layout Group — Spacing `5`, Child Alignment `Upper Left`, Force Expand·Control Size 전부 해제

`ItemShopBarUI._cards`는 **배열 순서 = 슬롯 인덱스**다. `[0]`이 진화의 돌, `[1]~[3]`이 일반 아이템. 어긋나면 돌 자리에 아이템이 뜬다.

## 5. 주의사항

### `RewardKind` enum 순서를 바꾸지 말 것 ⚠️

Unity는 enum을 **int로 직렬화**한다. 현재 순서:

```
... AugmentChoice(7), ItemShopReroll(8), Reforger(9)
```

`ItemShopReroll`을 지우면 `Reforger`가 9 → 8로 밀리면서, 이미 임포트된 `RewardDatabase.asset`의 **재련기 보상이 깨지고 기존 아이템샵리롤 항목이 재련기로 둔갑**한다. 리롤 기능을 폐기했더라도 enum 멤버는 남겨야 하는 이유다.

### 임포터 매핑도 남겨야 할 것 ⚠️

`ParseRewardKind`의 폴백이 `_ => RewardKind.Gold`다. `"itemShopReroll"` 매핑을 지우면 `reward_data.json`의 기존 행이 **골드 2 지급으로 조용히 둔갑**한다. 경고도 안 뜬다.

### 담당 파트 경계

`CLAUDE.md` 규칙상 상점/아이템/UI는 **태욱** 담당이다. 이번에 수정한 `ShopManager` / `RewardManager` / `GameEvents`는 태욱 영역이라 **사전 공유가 필요**하다. (해인이 전달 예정)

`UIManager.cs:76-77`에 미사용 필드 경고 2건(`_hoveredSampleDeckUnitIndex`, `_hoveredSampleDeckSynergyIndex`)이 있는데, 이번 작업과 무관한 기존 잔재다. 태욱 파트라 손대지 않았다.

### 디버그 바 중복

`PrototypeHud.cs:14`의 `_showShopDebugBar` 체크박스를 해제해야 IMGUI 임시 바(유닛·아이템 둘 다)가 꺼진다. 실 UI와 겹쳐 보이면 이것부터 확인.

### `ScriptableObject` using 누락

`ItemShopBarUI.cs`가 처음에 `using UnityEngine;` 없이 작성돼 CS0246/CS0311 3건이 났다. `UnitShopBarUI`는 `PokemonData`가 전역 타입이라 `System.Collections.Generic`만으로 충분했지만, `ScriptableObject`를 타입 인자로 쓰면 `UnityEngine`이 필요하다. 수정 완료.
