# 보상 시트 골드 증액 (2026-08-18)

레벨링 난이도 피드백에 대한 대응으로 **라운드 보상 골드를 전 라운드 일괄 +10** 한다.
이 문서는 왜 골드로 해결하는지, 왜 하필 +10인지를 수치 근거와 함께 남긴다.

**작성**: 황해인 (기획 디렉터)
**적용 대상**: 보상 시트(`reward_data.json` → `RewardDatabase`) RW001~RW005의 `gold` 항목
**상태**: 확정, 시트 반영 예정

---

## 1. 요약

| 항목 | 내용 |
|---|---|
| 문제 | 짧은 라운드 수(1-1~1-5)에 비해 레벨링이 어렵다는 의견 다수 |
| 원인 | ① 복제기 부재로 유닛 배급이 없음 ② 경험치 통이 라운드 수 대비 과대 |
| 해결 | 라운드 보상 골드 **전 라운드 +10** (총 +50G) |
| 대안 기각 | 복제기 신규 개발(일정상 불가), 경험치 통 축소(구조 변경 부담) |
| 검증 기준 | 경제 증강 선택 시 Lv10 도달이 "가능하지만 빠듯"할 것 |

---

## 2. 배경 — 무엇이 문제인가

### 2.1 3성작이 혼자서는 확률적으로 불리하다

레퍼런스 게임(롤토체스)은 여러 플레이어가 같은 풀을 공유한다. 다른 사람들이 자기 조합의 유닛을 빼가면서 **풀에서 다른 종이 줄어들고, 결과적으로 내가 노리는 종의 농도가 올라간다.** 혼자 하는 구조에서는 이 효과가 없다. 풀이 온전히 남아 있어 내 목표 종은 계속 전체 종 수만큼 희석된 상태다.

레퍼런스인 **톡톡이의 시험**은 이 문제를 **복제기**로 해결했다. 새로고침과 유닛 구매 없이도 유닛이 배급되므로 골드가 크게 절약된다.

포켓체스에는 복제기가 없다. 그래서 그만큼을 **골드로 보전**한다.

### 2.2 경험치 통이 라운드 수에 비해 크다

레퍼런스 게임은 수십 라운드에 걸쳐 진행되므로 경험치 요구량이 큰 것이 자연스럽다. 포켓체스는 1-1~1-5, **5라운드로 끝나는데 경험치 통은 긴 게임 기준 그대로**다. 코스트 n성작을 많이 한 플레이어는 이미 재화를 다 써서 레벨링이 사실상 막힌다.

---

## 3. 왜 이 방법인가 — 검토한 3가지

| 안 | 판단 | 사유 |
|---|---|---|
| 복제기 신규 구현 | **기각** | 디렉터 회의 결과, 현 시점에 새 기능을 넣기엔 일정상 불가능 |
| 경험치 통 축소 | **기각** | 레벨/확률/유닛 캡이 함께 물린 테이블이라 파급이 크다. 지금 시기에 손댈 범위가 아님 |
| **보상 골드 증액** | **채택** | 시트 수치만 바꾸면 되고, 복제기가 주던 가치를 골드로 환산해 대체할 수 있다 |

무료 리롤 횟수는 이미 라운드당 10회로 늘려 둔 상태이며, 이번 건과 별개로 유지한다(§6 참조).

---

## 4. 지급량 산정 근거

### 4.1 복제기 1세트는 골드로 얼마인가

복제기의 가치를 **유닛의 코인값(2+3+4=9G)** 으로 보면 안 된다. 복제기가 실제로 아껴 주는 것은 **그 유닛을 상점에서 찾아내는 비용**이다.

현재 게임 수치 기준으로 계산했다.

**전제**
- 상점 5칸, 리롤 2G
- 풀: 1코 12종×30장 / 2코 12종×25 / 3코 11종×18 / 4코 12종×10 / 5코 8종×9
- 등장 확률: Lv6 `30/40/25/5/0`, Lv7 `19/30/40/10/1`, Lv8 `15/20/32/30/3`
- **풀이 온전한 상태**를 가정 — 즉 §2.1에서 말한 "혼자라 풀이 안 빠지는" 불리한 조건이 이미 반영돼 있다

**특정 유닛 1장을 찾는 비용**

| 등급 | 대상 | 기준 레벨 | 슬롯당 확률 | 기대 리롤 | 리롤 골드 | 유닛값 | 소계 |
|---|---|---|---|---|---|---|---|
| 하급 | 2코스트 | Lv6 | 3.33% | 6.0회 | 12G | 2G | **14G** |
| 중급 | 3코스트 | Lv7 | 3.64% | 5.5회 | 11G | 3G | **14G** |
| 상급 | 4코스트 | Lv8 | 2.50% | 8.0회 | 16G | 4G | **20G** |
| | | | | | | **합계** | **48G** |

**여기에 이자가 붙는다.** 아낀 골드를 들고 있으면 10G당 1G(경제 증강 시 2G)가 라운드마다 붙는다. R2에 아껴 R5까지 굴리면:

| 등급 | 소계 | 이자 가산 | 실질 가치 |
|---|---|---|---|
| 하급 | 14G | +4 ~ +8G | 18 ~ 22G |
| 중급 | 14G | +4 ~ +8G | 18 ~ 22G |
| 상급 | 20G | +8 ~ +16G | 28 ~ 36G |
| **세트 합계** | **48G** | | **약 60 ~ 72G** |

> **참고 — 3성작의 실제 비용**
> 3코스트 3성 하나 = 카피 9장 = 기대 리롤 **49회**.
> 게임 전체에 지급되는 무료 리롤이 50회(라운드당 10회 × 5)이므로,
> **무료 리롤을 전부 써야 3성 한 마리**가 나온다. "혼자서 3성작이 어렵다"는 체감이 아니라 산수다.

### 4.2 레벨 문턱 대비 총 예산

**전제**
- XP 구매 환율 4G = 4XP → **1XP = 1G**
- 누적 필요 XP: Lv8 = 124, Lv9 = 200, Lv10 = 280
- 라운드 종료 XP 2 × 4회 = 8 (전투가 끝나야 들어오므로 R1 준비 시엔 0)
- 유닛 구매 최소선 80G (필드를 채우는 정도, 성작 제외)

| 목표 | 필요 XP 골드 | 유닛 | **문턱** |
|---|---|---|---|
| Lv8 | 116G | 80G | 196G |
| Lv9 | 192G | 80G | 272G |
| Lv10 | 272G | 80G | **352G** |

**총 예산 (시작 골드 10 + 보상 + 이자 최대치)**

| 안 | 증강 없음 | ECONOMY_GOLD 선택 시 |
|---|---|---|
| 현행 `10/25/40/55/70` | 230G | 300G |
| +5씩 `15/30/45/60/75` | 255G | 325G |
| **+10씩 `20/35/50/65/80`** | **280G** | **350G** |

※ ECONOMY_GOLD("골드를 획득했다!") = 즉시 +50G, 이자율 10G당 1 → 2 (라운드 상한 5G → 10G)

### 4.3 +5 vs +10 — 왜 +10인가

**세 가지 기준 모두 +10을 가리킨다.**

1. **복제기 세트 등가성**
   세트 실질 가치가 60~72G인데 +5씩은 총 **25G**로 세트의 **1/3 수준**에 그친다. +10씩(50G)이 등가에 가장 가깝다(여전히 약간 못 미친다).

2. **"경제 증강을 먹으면 Lv10에 간다"는 의도 충족**
   Lv10 문턱이 352G다.
   - 현행 + 증강 = 300G → **도달 불가** (현재 제기된 문제 그대로)
   - +5씩 + 증강 = 325G → **여전히 도달 불가**
   - **+10씩 + 증강 = 350G → 문턱에 닿음**

3. **경제 증강의 가치 보존**
   +10씩이면 증강 없이도 280G가 되어 Lv9(272G)가 열린다. **Lv10은 경제 증강을 먹어야 도달**하는 구조가 되어, 증강을 고르는 이유가 유지된다.

## 5. 결정 — 시트 반영 값

`reward_data.json`의 `gold` 항목만 수정한다. 나머지 항목(리롤 / 아이템 쿠폰 / 아이템샵 리롤 / 재련기)은 **변경 없음**.

| 테이블 | 라운드 | 스테이지 | 현행 | **수정** |
|---|---|---|---|---|
| RW001 | 1 | 야생·잉어킹 | 10 | **20** |
| RW002 | 2 | 관장·웅이 | 25 | **35** |
| RW003 | 3 | 관장·이슬이 | 40 | **50** |
| RW004 | 4 | 관장·목호 | 55 | **65** |
| RW005 | 5 | 챔피언·그린 | 70 | **80** |
| | | | 200G | **250G** |

정액 +10이므로 상대 증가율은 앞 라운드가 크다(R1 +100%, R5 +14%). 5라운드짜리 게임에서 **R1 골드는 이자와 성작으로 복리가 붙고 R5 골드는 마지막 전투 한 번에만 쓰이므로**, 이 방향이 맞다.

> 보상은 **해당 라운드 전투 시작 전에 선지급**된다(보상 → 상점 → 덱 구성 → 전투).
> 시트 라벨이 "N라운드 클리어 보상"으로 되어 있으나 실제 지급 시점은 **N라운드 시작 시**다. 라벨 표현은 추후 정리 대상.

## 7. 남는 제약 (인지하고 넘어가는 부분)

1. **이자 최대치 가정**
   위 예산표는 매 라운드 50G 이상을 들고 있어 이자를 최대로 받는다는 가정이다. 실제로는 골드를 쓰면서 플레이하므로 이자가 덜 붙는다. **+10씩이어도 Lv10은 "빠듯하게 가능" 수준이지 넉넉하지 않다.**

2. **Lv10과 3성작의 동시 달성은 여전히 불가**
   유닛 80G는 필드를 채우는 최소선이다. 성작을 적극적으로 하면 지출이 훨씬 커진다. 레벨이냐 성작이냐를 선택하게 되는데, **이는 의도된 선택 압력으로 본다.** 둘 다 가능하게 하려면 +20씩(총 +100G)까지 가야 하며, 그건 과하다고 판단했다.

3. **복제기는 여전히 미구현**
   이번 조치는 복제기의 **경제적 가치만** 대체한다. "원하는 유닛을 확정적으로 얻는다"는 복제기 고유의 경험은 대체되지 않는다. 일정에 여유가 생기면 재검토한다.

## 8. 적용 절차

1. 구글 시트에서 RW001~RW005의 `gold` 값을 위 표대로 수정
2. JSON 내보내기 → `Assets/Resources/Data/reward_data.json` 갱신
3. Unity에서 `PokeChess/Import Reward` 실행
4. `Assets/Resources/RewardDatabase.asset`에 값이 반영됐는지 대조

> **주의**: `RewardKind` enum의 순서를 바꾸거나 멤버를 지우지 말 것. Unity가 enum을 int로 직렬화하므로 임포트된 보상 종류가 통째로 어긋난다. 자세한 내용은 `CLAUDE.md`의 지뢰 항목 참조.
