# (오후 추가) 전적 Phase 2 — Supabase 로그인/DB 연동 완성

기획 답변 대기 시간에 전적 서버 업로드(Phase 2)를 끝까지 진행했습니다. **로그인(익명 세션) + DB + Unity 업로더까지 엔드투엔드 검증 완료입니다.**

### 5. 백엔드 결정 + DB 스키마 (`Docs/SCHEMA_2026-07-10_supabase-matches.sql`)
- 백엔드는 **Supabase**(PlayFab 대신), 인증은 **익명 + 닉네임**으로 확정
- `profiles`(익명 유저+닉네임) / `matches`(MatchRecord v1 미러 — 결과/라운드는 컬럼, 보드 스냅샷·시너지·증강은 jsonb)
- `unique(user_id, match_id)`로 중복 업로드 방지, **RLS**: 쓰기 본인만·전적 조회 본인만·닉네임 공개, update/delete 정책 없음(전적 불변)

### 6. Unity 업로더 (`Network/SupabaseMatchUploader.cs`)
- SDK 없이 **UnityWebRequest REST만 사용** (의존성 없음, 인수인계 고려)
- 시작 시 익명 세션 확보 — refresh_token을 PlayerPrefs에 보관해 기기당 계정 1개 유지
- `GameEvents.OnMatchRecorded` 구독 → 로컬 jsonl 기록 직후 자동 업로드. 실패해도 게임 영향 없음(로컬이 원본)
- GameSceneTest 씬 GameManager 오브젝트에 부착됨. 인스펙터의 anon key는 클라이언트 노출 전제 키(RLS가 방어선)라 커밋에 포함해도 안전합니다

### 7. 검증 결과
- curl E2E: 익명 로그인 / 프로필 upsert / 전적 insert / 본인 조회 / 중복 insert 무시 — 전부 통과
- 에디터 실플레이: 콘솔 `[Supabase] 전적 업로드 완료` + 서버 profiles에 유저 자동 생성 확인
- ⚠️ 라이브 전에 테스트 데이터 정리 필요: SQL Editor에서 `truncate public.matches; delete from public.profiles;`
