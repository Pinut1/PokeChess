# 패널 UI — 등급/시너지 수별 룩 변형 처리 방안 (2026-07-10)

같은 패널 디자인에서 등급·시너지 수에 따라 내부 룩만 바뀌는 UI를 어떻게 구현할지 논의 정리.
전제: **레이아웃은 동일하고 룩만 다름** + **등급별 완성 패널 이미지가 이미 있음**.

## 검토한 방법 3가지

| 방법 | 맞는 상황 | 문제점 |
|---|---|---|
| ① DOTween | — | 구조 선택지가 아님. "어떻게 갈아입힐까"(구조)가 아니라 "어떻게 움직일까"(연출) 도구. 어느 안을 골라도 연출용으로 병행 |
| ② 등급별 프리팹 + 데이터 참조 자동 교체 | 등급마다 **레이아웃 자체가 다를 때** (자식 구조·요소 개수가 다름) | 등급 N개 = 유지보수 지점 N개. 쓴다면 일반 복제가 아니라 **Prefab Variant**(베이스 1 + 오버라이드)로. 교체 시 Instantiate/Destroy 비용·깜빡임 |
| ③ 백 패널 1개 + 머터리얼 교체 | 이미지 1장을 **셰이더로** 변형해 등급 차이를 만들 때 (색조 시프트/디졸브/홀로그램) | UGUI에서 `image.material` 접근 시 머터리얼 인스턴스 증가 → 배칭 깨짐. 공유 머터리얼 수정 시 같은 머터리얼 쓰는 패널 전부 변경. UI 마스크와 충돌 |

## 결론: 프리팹 1개 + 스타일 SO + **스프라이트 스왑**

등급별 완성 이미지가 이미 있으므로 머터리얼이 할 일이 없음 — 단점만 떠안게 됨.

```csharp
panelImage.sprite = style.panelSprite; // 등급별 PanelStyle SO에서
```

- 패널 프리팹은 **하나**. `PanelStyle` ScriptableObject에 등급별 완성 패널 스프라이트 + 텍스트/핍 색상(HEX)을 담는다
- 패널의 스킨 컴포넌트가 `Apply(style)` 한 방으로 갈아입힘
- 등급 이미지들은 **SpriteAtlas 하나에** 묶기 → 교체해도 드로우콜 안 늘어남
- **시너지 수는 스타일이 아니라 데이터 바인딩 문제로 분리**: 최대 칸을 미리 깔고 활성/비활성 토글(TFT 핍처럼 칸 수 고정이면 이게 쌈) 또는 Layout Group + 셀 프리팹 복제
- DOTween은 그 위에 연출로: 등급 상승 플래시, 시너지 카운트 펀치 스케일 등
- "코드는 슬롯만 만들고 아트는 데이터(SO)만 꽂는다" — VfxDatabase와 같은 패턴 (인수인계 일관성)

## 주의점

1. **통짜 이미지는 9-슬라이스 불가** → 패널 크기 고정이 전제. 해상도 대응은 Canvas Scaler로 통째 스케일.
   패널 크기를 여러 종류로 쓸 계획이 생기면 그때 아트에게 프레임 분리 버전(9-슬라이스용)을 다시 요청
2. 텍스트/시너지 핍은 이미지에 굽지 말고 위에 별도 요소로 얹기
3. 머터리얼이 다시 필요해지는 시점 = "전설 등급 배경 일렁임" 같은 셰이더 연출이 생길 때.
   그 등급의 스타일 SO에만 선택적 머터리얼 필드를 추가하면 됨 (전면 도입 X)

## (참고) 나중에 부품 단위로 다시 받게 되면 — 아트 요청 규격

패널 크기 가변이 필요해져 통짜 이미지를 못 쓰게 될 때의 요청 기준:

- **프레임**: 등급 수만큼, 9-슬라이스 가능하게(모서리 장식은 코너에, 변은 반복 패턴). border 값 함께 전달. 사이즈/포맷 통일(예: 256×256 PNG 투명배경)
- **배경**: 무채색 1장 + 등급 색은 코드에서 `Image.color`로 (그라데이션/질감이 등급별로 다르면 그때만 추가)
- **색 팔레트**: 이미지가 아니라 등급별 HEX 값 표로 (스타일 SO에 들어갈 데이터)
- **글로우/장식**: 프레임에 굽지 말고 별도 스프라이트 (알파 페이드 연출용)
- **시너지 핍**: 빈 칸/채운 칸 상태별 2~3장만 (개수 복제는 코드 몫)
- **공통**: 네이밍 고정(`Panel_Frame_{등급}` 등), 저장 폴더 지정(예: `Assets/Art_UI/Panel/`), SpriteAtlas로 묶는다고 공지, 시안 1개 먼저 받아 9-슬라이스 검증 후 전량 진행
