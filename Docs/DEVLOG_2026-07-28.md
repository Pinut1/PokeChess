## 1. 인벤토리 실 UI + 유닛 드래그 장착

IMGUI 프로토타입(`ItemInventoryHud`)의 정식 uGUI 버전. 프로토타입 주석에 *"정식 uGUI 드래그앤드롭은 황해인 담당"* 으로 남아 있던 자리다.

### 백엔드는 손대지 않았다

`ItemManager.EquipToUnit(ScriptableObject, PokemonUnit)`이 이미 **장착 단일 입구**로 만들어져 있었다. 보유 검증 → `PokemonUnit` 슬롯 규칙 검사 → 인벤 제거를 전부 처리하고 `bool`을 돌려준다. UI는 드롭 시 이 함수만 부르면 끝이다.

| API | 용도 |
|---|---|
| `ItemManager.Items` / `.Stones` | 인벤토리 목록(읽기 전용) |
| `ItemManager.EquipToUnit` | 장착 단일 입구 |
| `GameEvents.OnInventoryChanged` | 변동 통지 |

### 신규 파일

- `UI/ItemSlotUI.cs` — 칸 1개. 아이콘 표시 + 드래그
- `UI/ItemInventoryUI.cs` — 20칸 동기화 + 드롭 지점 유닛 탐지 → 장착 위임

칸은 **고정 20개**(`MAX_INVENTORY_SIZE` = 씬 `itemBox_Panel` 20개)라 생성/파괴가 없다. 보유 목록을 앞칸부터 채우고 나머지는 `Clear()`. 아이템을 장착하면 목록이 당겨지고 맨 뒤 칸이 꺼진다.

드래그는 **아이템 표시부를 통째로 들어올린다**. `_itemView`(테두리 묶음의 루트)를 드래그 레이어로 옮겨 커서를 따라가게 하고, 놓으면 성공/실패와 무관하게 제자리로 되돌린다. 장착에 성공하면 `OnInventoryChanged`로 다시 그려지며 칸이 비므로 별도 롤백이 필요 없다.

### 배선하며 걸렸던 것 (재발 주의)

| 증상 | 원인 |
|---|---|
| 드래그가 아예 시작 안 됨 | 칸 루트 Image의 **Raycast Target이 꺼져** 있었다. 핸들러가 루트에 있어 여기가 켜져야 이벤트가 들어온다 |
| 테두리만 따라오고 일러스트가 안 옴 | `itemBox_Image`가 `itemBox_Line`의 **자식이 아니라 형제**였다. `m_Father`를 직접 확인해야 구조를 정확히 안다 |
| 계층을 고쳤는데 반영 안 됨 | **씬의 프리팹 인스턴스 안에서는 자식 재부모화가 불가능**하다. 프리팹 모드(Project 창에서 더블클릭)로 들어가서 고쳐야 한다 |

> 드래그 중 아이콘의 `raycastTarget`을 끄는 코드가 있었는데, 그게 오히려 이벤트 수신을 끊고 있어 제거했다. 드롭 판정은 `Physics.Raycast`(3D)라 UI raycastTarget과 무관하다.

## 2. 유닛 HP/마나 바

### 데이터 출처가 단계마다 다르다

| 단계 | 출처 | 위치 기준 |
|---|---|---|
| 전투 중 | `BattleManager.Units`(BattleUnit) — 실제로 HP가 깎이는 값 | `bu.visual`(전투 전용 인스턴스) |
| 그 외 | `BoardManager.GetUnitsOnBoard()` + `GetUnitsInBench()` | 유닛 Transform |

두 경로 모두 **기존 공개 API만 써서 `BattleManager`/`BoardManager`를 수정하지 않았다.**

### 폴링을 택한 이유

HP 변경 이벤트가 없고 `BattleManager`가 `currentHp`를 여러 곳에서 직접 감소시킨다. 이벤트를 심으려면 전투 코드를 여러 군데 고쳐야 하는데, 유닛이 수십 기 규모라 매 프레임 읽는 비용이 무시할 만하다.

### 눈금 (롤 체력바식 구분선)

바 폭은 고정인데 유닛마다 최대 체력이 달라 눈금 개수가 바뀌어야 한다. 스프라이트를 미리 그리는 대신 **`RawImage.uvRect.width`를 눈금 개수로 주어 텍스처를 반복**시킨다.

- `_hpPerTick` 기본 **150** — HP 범위(1성 300~1500, 3성 최대 약 4200) 기준. 100이면 최대 42칸이라 과밀
- 마나는 편차가 작아(manaCost 40~100) **고정 4칸**. `Awake`에서 한 번만 설정
- 텍스처: `Assets/Art/UI/Bar/bar_tick.png` (16×8, 선 1px = 셀 대비 6.25%)

> ⚠️ **텍스처 임포트 설정이 핵심이다.** `textureType: Default(0)` + `wrapU/wrapV: Repeat(0)`.
> Sprite 타입으로 바꾸면 Wrap이 **Clamp로 강제**되어 반복이 안 되고 마지막 픽셀만 늘어난다(선이 한 줄만 보임).
> 눈금 오버레이는 **`Image`가 아니라 `RawImage`** 여야 한다 — `uvRect`가 RawImage에만 있다.

### 배선 함정

`Hp_TickOverlay`의 RectTransform이 16×16으로 잡혀 있어 바(156) 왼쪽 끄트머리에만 걸쳐 있었다. **`Hp_Fill`과 같은 크기로 맞춰야** 한다. 단 `Hp_Fill`의 **자식으로 넣으면 안 된다** — `fillAmount`로 줄어들 때 눈금까지 잘린다.

### 픽셀 스냅

`WorldToScreenPoint` 결과를 그대로 쓰면 소수점 좌표에 배치돼, 1px 안팎의 얇은 선이 프레임마다 다른 텍셀에 걸린다. 유닛을 드래그하면 눈금이 두꺼워졌다 사라졌다 했다. **x/y를 `Mathf.Round`로 정수화**해 해결(성급 팝업도 동일 적용).

## 3. 진화 연출

### 이벤트 하나로 통합

진화가 세 군데에서 일어나고 있어 `GameEvents.OnUnitEvolved(unit, isStarUp)` 하나로 모았다.

| 경로 | 위치 | isStarUp |
|---|---|---|
| 성급 합체 | `BoardManager.CheckEvolution` | **true** |
| 진화의 돌 | `PokemonUnit.TryEquipStone` | false |
| 통신교환 | `NetworkManager` | false |

의도적으로 제외한 것: **돌 제거(`RemoveStone`)** 는 원복이지 진화가 아니고, **통신교환 베이스 핸드오버**는 진화체를 받은 게 아니다.

### 두 번의 버그와 원인

**① 합체 전 좌표에 이펙트가 떴다.**
`UnitPlaced`가 BoardView 위치 재배치를 트리거하는데 `UnitEvolved`를 그 **앞**에서 발화시켰다. 연출 시점엔 `transform.position`이 아직 옛 좌표다. 2성은 생존자가 제자리에 남는 경우가 많아 안 드러나다가 3성 연쇄에서 터졌다. → 재배치 뒤로 이동.

**② 3성 달성 시 중간 2성 자리에서도 이펙트가 났다.**
3성은 한 순간에 두 번 합체한다(1성×3 → 2성, 그 결과 2성이 3마리 → 3성). 단계마다 발화하고 있었다. → `CheckEvolution`이 **"이번 호출에서 실제로 합체했는지"** 를 반환하도록 바꾸고, 재귀가 `false`일 때(= 가장 깊은 단계)만 발화.

### 성급 팝업

`StarUpPopupUI` + `StarUpPopupHud`. HP바보다 위(`_heightOffset` 2.8 vs 2.0)에 떴다가 상승·페이드로 사라진다.

- 연쇄 진화로 동시에 여러 개가 뜰 수 있어 **풀링**
- 별 아이콘 배열에서 **앞에서부터 성급만큼 켠다**(2성=2개, 3성=3개). 별 1개짜리 이미지만 있으면 되고, 성급이 늘어도 아이콘만 추가하면 된다
- Horizontal Layout Group 아래 두면 꺼진 아이콘이 자리를 비워 자동 정렬된다

> HP바에도 상시 성급 표식을 넣었다가 **제거했다.** 순간 연출(팝업)만 쓰기로 결정.

## 4. 전투 화면 정리 (영욱 인수인계 완료 후 작업)

### 적 진영 타일 seam

적 진영 바닥이 `SpawnMirrorBoard`의 **런타임 생성 원기둥**(디버그용 평면)으로 고정돼 있었다. 아군 보드는 `_tilePrefab`으로 아트를 꽂을 수 있는데 적 진영만 통로가 없어, 아트를 넣어도 전투 화면 절반이 프리미티브였다.

`BattleManager._enemyTilePrefab`(HexTile) 추가. 비어 있으면 기존 원기둥으로 폴백한다.

생성 시 **상호작용을 자동으로 끈다**:
- `HexTile`은 `IDropTarget`이라 그대로 두면 **적 진영에 유닛이 놓인다** → 컴포넌트 비활성
- 콜라이더가 살아 있으면 **아이템 드래그 등 다른 `Physics.Raycast`를 가로챈다** → 전부 비활성
- 폴백 원기둥에도 콜라이더가 남아 있어 같이 제거

### 적 유닛 방향

`SpawnVisual`이 위치만 잡고 회전을 건드리지 않아, 적도 프리팹 기본 방향 그대로 아군과 같은 쪽을 보고 있었다. 보드가 점대칭 미러라 Y축 180도로 마주 본다. `rotation` 대입이 아니라 `Rotate(Space.World)`를 써서 모델의 기본 자세(기울기 등)를 덮어쓰지 않는다.

## 5. 평타 VFX 방향·거리

### 문제

`Spawn`이 항상 `Quaternion.identity`로 생성하고, 위치도 **대상**이었다. 그래서
- 방향성 프리팹이 누가 쐈든 같은 월드 방향을 향했고
- 전진하는 투사체가 **도착지에서 출발해 그 너머로 지나갔다**

### 해결 — 사거리로 나눔

`PlayBasicAttack(vfxId, attacker, target)` 신설.

| 사거리 | 연출 |
|---|---|
| 근접 (`range <= 1`) | 대상 위치에서 터지는 타격 이펙트(기존 동작) |
| 원거리 (`range > 1`) | **공격자에서 출발**해 대상 방향으로 발사 |

거리 맞춤은 **파티클 수명**으로 한다 — `수명 = 거리 ÷ Start Speed`. 프리팹 하나로 모든 거리에 대응된다. Start Speed가 0인 파티클(잔불·플래시)은 제자리 연출이라 건드리지 않는다. 자동 파괴는 이동 시간보다 짧아지지 않게 보정(+0.3s).

> 중간에 `VfxEntry.orientToDirection` 플래그를 뒀다가 **제거했다.** 방향이 실제로 보이는 건 원거리 평타뿐이고 스킬은 시전 위치에서 터지므로, 아트가 60종을 하나씩 판단할 이유가 없다. 회전 여부는 에셋이 아니라 **호출부가 결정**한다.

### 공속과 무관하다

발사 타이밍은 `attackCooldown`(= 1/attackSpeed)만 결정하고, 거리는 **이미 발사된 투사체의 이동 시간**에만 관여한다. 원거리 유닛 공속 0.30~0.70 → 간격 1.43~3.33초. 투사체 이동은 Start Speed 10 기준 0.2~1.0초라 항상 간격보다 짧아 겹치지 않는다.

### 프리팹 제작 조건

1. **`+Z`가 정면** — 회전이 Z축 기준
2. **Start Speed로 전진** — Velocity over Lifetime이나 애니메이션으로 움직이면 수명 계산이 안 먹는다
3. **Simulation Space = `World`** — `Local`이면 부모를 따라다녀 발사가 아니라 붙어 있는 것처럼 보인다
4. 피해는 **발사 순간에 적용**된다. 이동이 길면 HP가 먼저 깎이므로 Start Speed를 넉넉히(15~20) 잡는 게 좋다
